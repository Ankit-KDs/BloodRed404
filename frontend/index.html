Process Flow

How RED404 Works

01

Donor Registers

Donors register with name, blood type, location, and contact info. Their coordinates are indexed into zone buckets.

02

Hospital Raises Request

When blood is needed, hospital triggers a request specifying blood type and urgency level from their dashboard.

03

Zone Search Begins

Haversine algorithm scans Zone 1 (0–5km) first, then Zone 2 (5–10km), expanding outward using BFS-like zone traversal.

04

Notification Sent

Eligible donors receive real-time push notifications on their phones with blood type, hospital name, and distance.

05

Route Provided

On acceptance, Dijkstra's algorithm calculates the optimal route. Donor receives turn-by-turn navigation to the hospital.

06

Life Saved

Donor arrives, donates blood, and the request is fulfilled. System updates donor history, badges, and stats.

Under The Hood

Algorithms Powering RED404

Haversine Formula

Calculates great-circle distances between GPS coordinates for accurate zone assignment.

d = 2r·arcsin(√(sin²(Δφ/2)+cos φ₁·cos φ₂·sin²(Δλ/2)))

Dijkstra's Shortest Path

Finds the shortest weighted path from donor to hospital through the city road graph.

Priority Queue + Relaxation

BFS Zone Traversal

Breadth-first search expands zone-by-zone outward from hospital when searching for donors.

Queue-based Level Traversal

Priority Queue

Donors sorted by distance and compatibility. Nearest eligible donor served first (min-heap).

Min-Heap O(log n)

Hash Map Lookup

O(1) blood type to donor list mapping. Instantly retrieves all donors of a specific blood type.
